# AI가 계산하는 방식을 흉내 내는 작은 계산기 만들기

Python으로 **MAC(Multiply-Accumulate) 연산과 간단한 패턴 분류 과정을 직접 구현한 콘솔 기반 Mini NPU Simulator**입니다.

패턴과 필터를 NxN 행렬로 표현하고, 같은 위치의 값을 곱해 누적한 MAC 점수를 비교하여 입력 패턴을 분류합니다.  
또한 JSON 테스트 데이터 분석, 입력값 검증, 부동소수점 동점 처리, 행렬 크기별 실행 시간 측정, 2차원/1차원 MAC 구현 비교를 포함합니다.

---

## 1. 프로젝트 목표

이 프로젝트에서는 다음 내용을 직접 구현하는 것을 목표로 했습니다.

- NxN 숫자 행렬 표현 및 검증
- 반복문 기반 MAC 연산 구현
- 두 필터의 MAC 점수를 이용한 패턴 분류
- 부동소수점 오차를 고려한 점수 비교
- `data.json` 기반 테스트 데이터 분석
- 잘못된 입력 및 데이터에 대한 예외 처리
- 3×3, 5×5, 13×13, 25×25 크기의 성능 비교
- 2차원 행렬 접근과 1차원 배열 접근 방식 비교

NumPy와 같은 외부 행렬 라이브러리는 사용하지 않고 Python 반복문으로 MAC 연산을 직접 구현했습니다.

  - `json`: JSON 파일 읽기


## 3. 프로그램 실행 모드

프로그램을 실행하면 두 가지 모드 중 하나를 선택합니다.

```text
=== Mini NPU Simulator ===

[모드 선택]

1. 사용자 입력 (3x3)
2. data.json 분석
선택:
```

### 모드 1. 사용자 입력

사용자가 직접 다음 데이터를 입력합니다.

1. 3×3 필터 A
2. 3×3 필터 B
3. 3×3 입력 패턴

각 행은 숫자 3개를 공백으로 구분하여 입력합니다.

```text
0 1 0
1 1 1
0 1 0
```

입력이 끝나면 두 필터에 대한 MAC 점수를 계산하고 다음 중 하나로 판정합니다.

```text
A
B
판정 불가
```

두 점수의 차이가 `epsilon`보다 작으면 특정 필터를 임의로 선택하지 않고 `판정 불가`로 처리합니다.

### 모드 2. data.json 분석

```text

      ↓
패턴별 크기 확인
      ↓
해당 크기의 필터 선택
      ↓
Matrix 객체 생성
      ↓
Cross / X MAC 계산
      ↓
점수 비교 및 분류
      ↓
expected와 비교
      ↓
PASS / FAIL
      ↓
성능 분석
      ↓
전체 결과 요약
```

# 6. main.py

`main.py`는 프로그램의 진입점입니다.

```python
from simulator import Simulator


def main():
    simulator = Simulator()
    simulator.run()


if __name__ == "__main__":
    main()
```

`main.py`에서는 직접 입력을 처리하거나 MAC 연산을 수행하지 않습니다.

프로그램을 시작한 뒤 실제 실행은 `Simulator`에게 맡깁니다.

```text
main.py
   ↓
Simulator()
   ↓
run()
```

이렇게 하면 프로그램의 시작 코드와 실제 기능 구현이 섞이지 않고, 처음 코드를 보는 사람도 실행 지점을 쉽게 찾을 수 있습니다.

# 7. Matrix 클래스

`Matrix`는 패턴과 필터에 공통으로 사용하는 **NxN 숫자 행렬을 표현하는 클래스**입니다.

일반적인 Python 2차원 리스트를 그대로 전달하며 계산할 수도 있지만, 행렬 데이터와 행렬 검증을 한 곳에서 관리하기 위해 `Matrix` 객체로 감쌌습니다.

```text
2차원 list
    ↓
  Matrix
```

## 주요 메서드

| 메서드 | 역할 |
|---|---|
| `__init__(values)` | 행렬 데이터를 저장하고 즉시 검증 |
| `size` | 행렬 한 변의 크기 반환 |
| `get(row, col)` | 특정 위치의 값 조회 |
| `set(row, col, value)` | 특정 위치의 값 변경 |
| `_validate()` | NxN 구조 및 숫자 데이터 검증 |
| `flatten()` | 2차원 행렬을 1차원 배열로 변환 |

## 생성 시점 검증

```python
def __init__(self, values):
    self.values = values
    self._validate()
```

객체를 만든 뒤 나중에 잘못된 행렬임을 발견하는 것보다, 생성되는 순간부터 정상적인 행렬만 사용하도록 `_validate()`를 호출했습니다.

`_validate()`에서는 다음을 확인합니다.

- 비어 있는 행렬인지
- 모든 행이 리스트인지
- 행과 열의 길이가 같은 NxN 형태인지
- 모든 값이 `int` 또는 `float`인지

따라서 NPU는 전달받은 `Matrix`가 기본적인 행렬 검증을 통과했다는 전제에서 계산할 수 있습니다.

## `size`

행렬 한 변의 크기를 반환합니다.

```python
matrix.size
```

크기는 행동보다 객체가 가진 속성에 가깝기 때문에 `@property`를 사용했습니다.

## `get()` / `set()`

NPU가 `matrix.values[row][col]`처럼 내부 리스트 구조를 직접 사용하지 않고 다음과 같이 Matrix가 제공하는 메서드를 통해 값에 접근하도록 했습니다.

```python
pattern.get(row, col)
filter_.get(row, col)
```

`set()`에서는 새 값도 숫자인지 검사하여 잘못된 타입의 데이터가 들어가는 것을 방지합니다.

## `flatten()`

다음과 같은 2차원 행렬을

```text
1 2 3
4 5 6
7 8 9
```

행 순서의 1차원 배열로 변환합니다.

```text
[1, 2, 3, 4, 5, 6, 7, 8, 9]
```

2차원 접근 방식과 1차원 접근 방식의 MAC 실행 시간을 비교하기 위해 사용합니다.

# 8. NPU 클래스

`NPU`는 실제 계산을 담당하는 핵심 클래스입니다.

```text
NPU
├── MAC 계산
├── 1차원 MAC 계산
├── 점수 비교
├── 패턴 분류
└── 실행 시간 측정
```

NPU에는 사용자 입력, 화면 출력, JSON 파일 읽기 로직을 넣지 않았습니다.

즉, 데이터를 어디에서 가져왔는지가 아니라 **전달받은 데이터를 어떻게 계산할 것인지**에만 집중합니다.

---

## 8.1 MAC 연산

MAC은 `Multiply-Accumulate`의 약자로, 곱셈 결과를 계속 누적하는 연산입니다.

현재 구현에서는 패턴과 필터의 같은 위치 값을 곱한 뒤 모든 결과를 더합니다.

```text
score = Σ(pattern[row][col] × filter[row][col])
```

코드는 중첩 반복문으로 직접 구현했습니다.

```python
result = 0

for row in range(pattern.size):
    for col in range(pattern.size):
        result += pattern.get(row, col) * filter_.get(row, col)
```

NumPy를 사용하면 더 짧게 구현할 수 있지만, 이 프로젝트에서는 MAC의 `Multiply → Accumulate` 과정이 코드에서 직접 보이도록 반복문으로 구현했습니다.

또한 두 행렬의 크기가 다르면 같은 위치끼리 계산할 수 없으므로 연산 전에 크기를 비교합니다.

---

## 8.2 점수 비교와 epsilon

두 필터의 점수는 다음처럼 비교합니다.

```python
diff = score_a - score_b
```

다만 부동소수점 계산 결과는 수학적으로 같은 값이어도 아주 작은 오차가 발생할 수 있습니다.

예를 들어 다음 두 값은 계산 목적상 같은 값으로 봐야 할 수 있습니다.

```text
0.9000000000000000
0.8999999999999999
```

따라서 `score_a == score_b`로 직접 비교하지 않고 허용 오차인 `epsilon`을 사용합니다.

기본값은 다음과 같습니다.

```python
epsilon = 1e-9
```

두 점수의 차이가 다음 조건을 만족하면 동점으로 처리합니다.

```text
|score_a - score_b| < epsilon
```

---

## 8.3 classify()

`classify()`는 MAC 계산과 점수 비교를 조합해 최종 결과를 만드는 메서드입니다.

```text
                Pattern
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
     Filter A              Filter B
        │                     │
        ▼                     ▼
      MAC A                 MAC B
        │                     │
        └──────────┬──────────┘
                   ▼
            compare_scores()
                   │
       ┌───────────┼───────────┐
       ▼           ▼           ▼
    A가 큼        동점       B가 큼
       │           │           │
    label A    UNDECIDED    label B
```

사용자 입력 모드와 JSON 모드에서 같은 계산 코드를 재사용하기 위해 결과 라벨을 매개변수로 전달합니다.

```text
사용자 입력 모드
label_a = "A"
label_b = "B"

JSON 분석 모드
label_a = "Cross"
label_b = "X"
```

NPU 내부에 `Cross`, `X`를 고정하지 않았기 때문에 같은 분류 로직을 두 모드에서 재사용할 수 있습니다.

# 9. DataLoader 클래스

`DataLoader`는 외부의 `data.json`을 읽고 프로그램에서 사용할 수 있는 형태로 해석합니다.

```text
data.json
    ↓
DataLoader
    ↓
Python dictionary
```

NPU가 JSON 파일 위치나 JSON 구조까지 알아야 하지 않도록 외부 데이터 처리를 별도 책임으로 분리했습니다.

## 주요 메서드

| 메서드 | 역할 |
|---|---|
| `load()` | JSON 파일 읽기 |
| `validate_schema()` | JSON 최상위 구조 확인 |
| `extract_size()` | 데이터 키에서 행렬 크기 추출 |
| `normalize_label()` | 라벨을 `Cross`, `X`로 통일 |

---

## 9.1 JSON 로드

```python
with open(self.path, "r", encoding="utf-8") as file:
    data = json.load(file)
```

`with open()`을 사용하여 파일 사용이 끝난 후 자동으로 닫도록 했고, UTF-8 인코딩을 명시했습니다.

JSON을 읽은 뒤 바로 `validate_schema()`를 호출하여 최소한의 기본 구조를 확인합니다.

---

## 9.2 기본 스키마 검증

JSON의 최상위 데이터는 다음 구조를 가져야 합니다.

```json
{
  "filters": {},
  "patterns": {}
}
```

다음을 검사합니다.

- JSON 최상위 값이 객체인지
- `filters`가 존재하는지
- `patterns`가 존재하는지
- `filters`와 `patterns`가 객체 형태인지

여기에서는 전체 파일의 기본 구조만 확인합니다.

특정 필터나 패턴 하나의 문제 때문에 전체 JSON을 사용할 수 없게 만들지 않도록, 개별 데이터의 세부 검증은 실제 해당 데이터를 처리하는 과정에서 수행합니다.

---

## 9.3 크기 추출

JSON 키는 다음과 같은 형태를 사용합니다.

```text
size_5
size_13
size_25

size_5_1
size_13_2
size_25_1
```

`extract_size()`는 `_` 기준으로 문자열을 나누고 두 번째 값을 정수로 변환합니다.

```text
size_13_2
   ↓
["size", "13", "2"]
   ↓
13
```

패턴 키가 `size_13_2`라면 `13`을 추출하고 다음 필터를 자동으로 선택할 수 있습니다.

```text
size_13
```

따라서 각 테스트 케이스에 사용할 필터를 코드에 직접 하드코딩하지 않아도 됩니다.

---

## 9.4 라벨 정규화

JSON에는 같은 의미의 라벨이 여러 문자열로 표현될 수 있습니다.

```text
"+"      ┐
"cross"  ├──→ Cross
"Cross"  ┘

"x"      ┐
"X"      ┴──→ X
```

프로그램 내부에서는 `Cross`, `X`만 사용하도록 통일합니다.

라벨을 먼저 정규화하면 이후 판정 코드에서는 원본 데이터가 `+`였는지 `cross`였는지를 신경 쓸 필요 없이 단순하게 비교할 수 있습니다.

# 10. Simulator 클래스

`Simulator`는 프로그램 전체 실행 순서를 관리합니다.

직접 MAC 공식이나 JSON 파싱 방법을 구현하는 것이 아니라 `Matrix`, `NPU`, `DataLoader`를 연결합니다.

```text
Matrix      → 데이터
NPU         → 계산
DataLoader  → 외부 데이터

        ↓ 연결

     Simulator
```

생성 시 NPU와 DataLoader 객체를 준비합니다.

```python
self.npu = NPU()
self.data_loader = DataLoader(data_path)
```

---

## 10.1 사용자 입력 모드 흐름

```text
Simulator.run()
       ↓
사용자 모드 선택
       ↓
_run_user_input_mode()
       ↓
필터 A 입력 ──→ Matrix
필터 B 입력 ──→ Matrix
패턴 입력   ──→ Matrix
       ↓
NPU.classify()
       ↓
MAC A / MAC B
       ↓
점수 비교
       ↓
A / B / UNDECIDED
       ↓
평균 실행 시간 측정
       ↓
결과 출력
```

필터 A, 필터 B, 패턴은 모두 같은 방식으로 입력되므로 공통 입력 로직을 `_input_matrix()`로 분리했습니다.

이를 통해 같은 입력 코드를 세 번 반복하지 않고 재사용합니다.

---

## 10.2 JSON 분석 모드 흐름

JSON 분석 모드는 크게 다음 단계로 진행됩니다.

```text
1. JSON 로드
2. 필터 준비
3. 패턴 분석
4. 성능 분석
5. 결과 요약
```

### 1단계. JSON 로드

`DataLoader.load()`로 JSON 파일을 읽습니다.

파일을 열 수 없거나 기본 JSON 구조가 잘못되면 분석 자체를 진행할 수 없으므로 오류 메시지를 출력하고 JSON 모드를 종료합니다.

### 2단계. 필터 준비

각 크기의 필터에 대해 다음을 확인합니다.

```text
필터 데이터가 객체인지
       ↓
라벨 정규화
       ↓
Cross / X → Matrix
       ↓
Cross와 X가 모두 존재하는지
       ↓
키에 적힌 크기와 실제 크기가 같은지
```

정상적으로 읽은 필터는 `loaded_filters`에 저장합니다.

잘못된 필터는 전체 프로그램을 종료하지 않고 `filter_errors`에 오류 원인을 저장합니다.

따라서 예를 들어 `size_13` 필터에 문제가 있어도 정상적인 다른 크기의 필터는 계속 처리할 수 있습니다.

### 3단계. 패턴 분석

각 패턴마다 다음 순서로 처리합니다.

```text
패턴 데이터 구조 확인
       ↓
input / expected 존재 확인
       ↓
패턴 키에서 크기 추출
       ↓
해당 크기의 필터 찾기
       ↓
입력 데이터를 Matrix로 변환
       ↓
키의 크기와 실제 Matrix 크기 비교
       ↓
expected 라벨 정규화
       ↓
NPU.classify()
       ↓
expected와 결과 비교
       ↓
PASS / FAIL
```

각 패턴을 개별 `try-except`로 처리합니다.

한 케이스의 데이터가 잘못되어도 프로그램 전체가 중단되지 않고 해당 케이스만 실패 목록에 기록한 뒤 다음 패턴을 계속 분석합니다.

### 4단계. 성능 분석

다음 크기를 대상으로 MAC 실행 시간을 측정합니다.

```text
3×3
5×5
13×13
25×25
```

각 크기에 대해 동일한 값으로 이루어진 행렬을 사용합니다.

성능 비교의 목적은 패턴 내용 자체가 아니라 **행렬 크기가 커질 때 연산량과 실행 시간이 어떻게 변하는지 확인하는 것**이기 때문입니다.

### 5단계. 결과 요약

분석이 끝나면 다음 정보를 출력합니다.

```text
총 테스트 개수
PASS 개수
FAIL 개수
실패한 케이스와 원인
```

# 11. 예외 처리 및 입력 검증

프로그램이 잘못된 입력 하나 때문에 바로 종료되지 않도록 입력 위치와 데이터 경계에서 검증합니다.

| 상황 | 처리 |
|---|---|
| 메뉴에 문자를 입력 | 숫자 입력 안내 후 다시 입력 |
| 메뉴에 1, 2 이외의 숫자를 입력 | 다시 입력 |
| 행렬 입력에 문자가 포함됨 | 해당 행 다시 입력 |
| 한 행의 숫자 개수가 부족하거나 많음 | 해당 행 다시 입력 |
| 빈 Matrix | `ValueError` |
| NxN 형태가 아닌 Matrix | `ValueError` |
| 숫자가 아닌 Matrix 원소 | `ValueError` |
| 패턴과 필터 크기가 다름 | `ValueError` |
| JSON 파일을 읽지 못함 | 오류 출력 후 JSON 모드 종료 |
| JSON 최상위 구조가 잘못됨 | 오류 출력 후 JSON 모드 종료 |
| 특정 필터가 잘못됨 | 해당 필터 오류 기록 후 다른 필터 계속 처리 |
| 특정 패턴이 잘못됨 | 해당 케이스 FAIL 처리 후 다음 패턴 계속 분석 |
| 알 수 없는 라벨 | 해당 데이터 오류 처리 |
| 두 점수가 epsilon 이내 | `UNDECIDED` |

오류 처리는 크게 두 경우로 나눴습니다.

### 전체 분석을 진행할 수 없는 오류

예:

```text
data.json 파일 자체를 읽을 수 없음
filters / patterns 최상위 구조가 없음
```

이 경우에는 JSON 분석을 종료합니다.

### 일부 데이터만 잘못된 오류

예:

```text
특정 패턴의 input 누락
특정 expected 누락
특정 Matrix의 크기 오류
특정 필터 오류
```

이 경우에는 전체 프로그램을 종료하지 않고 해당 데이터의 실패 원인만 기록한 뒤 다음 데이터를 계속 분석합니다.

# 12. 성능 분석

NxN 행렬에는 총 `N²`개의 원소가 있습니다.

현재 MAC 구현은 모든 위치를 한 번씩 방문합니다.

```text
3×3   → 9
5×5   → 25
13×13 → 169
25×25 → 625
```

따라서 입력 크기를 N이라고 할 때 MAC 계산의 시간 복잡도는 다음과 같이 볼 수 있습니다.

```text
O(N²)
```

현재 출력의 `연산 횟수`는 **필터 하나에 대한 위치별 MAC 횟수**를 의미합니다.

실제 `classify()`에서는 동일한 패턴에 필터 A와 필터 B를 각각 적용하므로 MAC 계산을 두 번 수행합니다.

---

## 12.1 실행 시간 측정

`time.perf_counter()`를 사용하여 MAC 함수 실행 전후 시간을 측정합니다.

한 번의 실행 시간만 사용하지 않고 기본적으로 10회 반복한 뒤 평균을 계산합니다.

```text
MAC 실행
  × 10회
    ↓
전체 시간 합계
    ↓
10으로 나눔
    ↓
평균 실행 시간(ms)
```

매우 짧은 실행 시간을 측정하기 때문에 운영체제 스케줄링, CPU 상태 등에 따라 측정값은 실행할 때마다 달라질 수 있습니다.

---

## 12.2 2차원 방식과 1차원 방식 비교

기본 구현은 `Matrix.get(row, col)`을 사용하여 2차원으로 접근합니다.

```text
row
 └─ col
```

비교 구현에서는 먼저 `flatten()`으로 1차원 리스트를 만들고 하나의 인덱스로 순회합니다.

```text
index
```

두 방식 모두 같은 위치의 값을 곱해 누적하므로 계산 결과는 같아야 합니다.

현재 비교는 실제 NPU 하드웨어의 성능을 측정하는 벤치마크가 아니라 **Python에서 작성한 두 MAC 루프의 접근 방식에 따른 실행 시간 차이를 확인하기 위한 실험**입니다.

또한 `flatten()` 변환 자체의 시간은 MAC 실행 시간 측정에 포함하지 않습니다.

따라서 결과는 절대적인 하드웨어 성능이 아니라 현재 Python 구현의 비교 결과로 해석해야 합니다.

# 13. 현재 data.json 분석 결과

현재 제공된 `data.json`을 기준으로 실행하면 총 6개의 테스트 케이스를 분석합니다.

| 케이스 | 판정 | expected | 결과 |
|---|---|---|---|
| `size_5_1` | `UNDECIDED` | `X` | FAIL |
| `size_5_2` | `Cross` | `Cross` | PASS |
| `size_13_1` | `X` | `X` | PASS |
| `size_13_2` | `UNDECIDED` | `Cross` | FAIL |
| `size_25_1` | `UNDECIDED` | `X` | FAIL |
| `size_25_2` | `Cross` | `Cross` | PASS |

최종 결과는 다음과 같습니다.

```text
총 테스트: 6개
통과: 3개
실패: 3개
```

세 개의 FAIL 케이스는 모두 Cross와 X 점수의 차이가 `epsilon`보다 작아 `UNDECIDED`로 처리된 경우입니다.

즉 단순히 소수점 마지막 자리의 미세한 차이를 이용해 Cross 또는 X를 선택하지 않고, 현재 비교 정책에 따라 동점으로 처리한 결과입니다.

`UNDECIDED`는 `expected`의 `Cross` 또는 `X`와 같지 않기 때문에 해당 테스트는 FAIL로 집계됩니다.

| `size_5_1` | `UNDECIDED` | `X` | FAIL |
x 모양의 패턴을 갖고 있지만 필터가 가진 가중치가 작아 MAC연산 이후 스코어가 작게 나와 제대로된 분류가 되지 않는다.

| `size_13_2` | `UNDECIDED` | `Cross` | FAIL |
5_1 과 마찬가치로 필터에 부여된 가중치가 적어 가중치가 높은 중앙에 위치한 셀의 영향을 크게 받아 제대로된 분류가 되지 않았다.

| `size_25_1` | `UNDECIDED` | `X` | FAIL |
위와 같은 이유로 x 필터에 부여된 가중치가 적어 제대로된 분류가 되지 않았다.

# 14. 주요 설계 선택

## 계산과 입출력 분리

NPU는 MAC 계산 방법만 알고 사용자 입력이나 JSON 파일 형식은 알지 않습니다.

```text
Simulator → 실행 흐름
NPU       → 계산
Matrix    → 데이터
DataLoader→ 외부 데이터
```

이렇게 분리하면 입력 방식이 변경되어도 MAC 계산 코드를 그대로 사용할 수 있습니다.

## Matrix 객체 사용

패턴과 필터를 일반 리스트 그대로 전달하지 않고 Matrix 객체로 표현했습니다.

행렬에 필요한 검증과 접근 기능을 한 클래스에서 관리하여 다른 코드가 데이터 검증 로직을 반복하지 않도록 했습니다.

## 공통 분류 로직 재사용

사용자 입력 모드와 JSON 모드가 서로 다른 결과 이름을 사용하지만 계산 과정은 동일합니다.

`classify()`가 결과 라벨을 매개변수로 받도록 하여 같은 로직을 재사용했습니다.

## 개별 JSON 오류 격리

하나의 테스트 케이스가 잘못됐다고 전체 분석을 중단하지 않습니다.

테스트 프로그램의 목적에 맞게 정상 데이터는 끝까지 분석하고 잘못된 케이스만 실패 원인과 함께 기록합니다.

## 과도한 구조 분리 방지

입력 처리, 출력, 성능 분석 등을 모두 별도 클래스로 만들 수도 있지만 현재 과제 규모에서는 오히려 전체 구조를 복잡하게 만들 수 있다고 판단했습니다.

따라서 핵심 책임만 `Matrix`, `NPU`, `DataLoader`, `Simulator`로 분리했습니다.

# 15. 현재 한계와 개선 가능 항목

현재 구현은 과제에서 요구하는 핵심 동작과 MAC 연산 원리를 명확하게 보여주는 것을 우선했습니다.

추가로 개선할 수 있는 부분은 다음과 같습니다.

### 1. 자동 테스트

현재 클래스 구조는 계산 코드와 입출력 코드가 분리되어 있기 때문에 단위 테스트를 추가하기 쉽습니다.

예를 들어 다음 기능을 독립적으로 검증할 수 있습니다.

```text
Matrix 정상/비정상 생성
MAC 계산 결과
서로 다른 크기 행렬 거부
epsilon 동점 처리
라벨 정규화
잘못된 JSON 기본 구조
키에서 크기 추출
```

### 2. data.json 경로 처리

현재 기본 경로는 `"data.json"`이므로 프로젝트 디렉터리에서 실행하는 것을 전제로 합니다.

`Path(__file__)`을 기준으로 경로를 계산하도록 변경하면 다른 작업 디렉터리에서 실행해도 프로젝트의 `data.json`을 찾도록 개선할 수 있습니다.

### 3. Matrix 데이터 보호

현재 `values` 속성에 외부에서 직접 접근할 수 있습니다.

필요하다면 내부 데이터 접근을 제한하거나 복사본을 사용하여 생성 후 검증되지 않은 방식으로 값이 변경되는 것을 더 강하게 방지할 수 있습니다.

### 4. 성능 측정 정밀화

현재는 10회 평균을 사용합니다.

더 정밀한 성능 분석이 필요한 경우 다음을 추가할 수 있습니다.

```text
반복 횟수 증가
warm-up 실행
최소/최대/중앙값 측정
timeit 사용
flatten 변환 시간 포함/제외 결과 분리
```

# 16. 전체 데이터 흐름

프로그램 전체를 데이터 관점에서 보면 다음과 같습니다.

```text
사용자 입력 / data.json
          ↓
       DataLoader
       (JSON 모드)
          ↓
        Matrix
          ↓
         NPU
          ↓
MAC 점수 / 분류 결과
          ↓
      Simulator
          ↓
       화면 출력
```

사용자 입력 모드에서는 DataLoader를 거치지 않고 입력 데이터를 바로 Matrix로 변환합니다.

```text
사용자 입력
    ↓
  Matrix
    ↓
   NPU
    ↓
Simulator 출력
```

JSON 모드에서는 DataLoader가 외부 데이터를 읽고 해석한 뒤 Matrix와 NPU로 전달합니다.

```text
data.json
    ↓
DataLoader
    ↓
  Matrix
    ↓
   NPU
    ↓
PASS / FAIL
    ↓
Simulator 출력
```

# 17. 정리

이 프로젝트는 MAC 연산을 단순히 함수 하나로 구현하는 데서 끝내지 않고, 프로그램 내부 책임을 다음과 같이 분리했습니다.

```text
Matrix
→ 계산에 사용할 행렬 데이터와 검증

DataLoader
→ 외부 JSON 데이터 읽기와 해석

NPU
→ MAC 연산, 점수 비교, 패턴 판정, 성능 측정

Simulator
→ 사용자 입력과 JSON 분석의 전체 실행 흐름

main.py
→ 프로그램 시작
```

핵심 설계 방향은 **데이터, 계산, 외부 데이터 처리, 실행 흐름을 분리하되 과제 규모에 맞게 구조를 지나치게 복잡하게 만들지 않는 것**입니다.

이를 통해 각 클래스가 맡은 역할을 구분하고, 동일한 MAC 및 분류 로직을 서로 다른 실행 모드에서 재사용할 수 있도록 구현했습니다.
